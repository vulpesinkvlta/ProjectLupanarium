# Версии игры и сборка для Яндекс Игр

Готовый проверенный архив: **Builds/Yandex-2026-09-28.zip** (19,4 МБ). [Результаты проверки и ограничения](VERIFICATION.md).

## Где собраны каталоги

Главная точка настройки — **Assets/Prefabs/ProjectLifetimeScope.prefab**, компонент **ProjectLifetimeScope**.
Он назначен в поле **RootLifetimeScope** ассета **Assets/Prefabs/VContainerSettings.asset**.
VContainer автоматически создаёт корневой scope; он переживает смену сцен. Это не объект, который нужно копировать в каждую сцену.
Поля префаба регистрируются через `RegisterInstance`; сцены получают их через инъекцию в конструкторы и `[Inject]`.

| Поле корневого scope | Текущий ассет |
|---|---|
| Run Config | Assets/Configs/Run/RunConfig.asset |
| Contract Catalog | Assets/Configs/Wave/ContractCatalog.asset |
| Upgrade Catalog | Assets/Configs/Upgrades/UpgradeCatalog.asset |
| Blessing Catalog | Assets/Configs/Blessings/BlessingCatalog.asset |
| Formation Catalog | Assets/Configs/Formations/FormationCatalog.asset |
| School Catalog | Assets/Configs/Buildings/SchoolCatalog.asset |
| Item Catalog | Assets/Configs/Equipment/ItemCatalog.asset |
| Roster Catalog | Assets/Configs/Run/RosterCatalog.asset |
| Class Catalog | Assets/Configs/UI/HealthView.asset |

Активная система волн использует **ContractCatalog**, а не старые WaveConfig. Ссылки на UnitConfig находятся в ростере, стартовом составе RunConfig, контрактах и наградах пополнения.
Визуальные спрайты и анимации задаются отдельно: общий префаб **Assets/Prefabs/Units/UnitView.prefab** и его поле каталога анимаций. Проверьте также ссылки HUD на каталог классов в сценах.

Для отдельной версии скопируйте корневой префаб и каталоги вместе с зависимыми ассетами, замените ссылки в копии, затем назначьте нужный корневой префаб в VContainerSettings перед сборкой.
Одного копирования каталога недостаточно: если обе копии ссылаются на один UnitConfig или предмет, правка этого ассета изменит обе версии.
В пределах каждой версии ID должны быть непустыми, уникальными и стабильными после публикации. Enum UnitClassId пока общий для кода; заменять имена и картинки можно через каталоги, новые механические классы требуют расширения enum и проверок.

Контентные конфиги этой задачей не изменялись. Автоматического переключателя гладиаторы/брейнроты нет: выбор каталога остаётся за разработчиком.

## Что добавлено

Официальный HTML5 SDK загружается из `/sdk.js` в шаблоне **Assets/WebGLTemplates/Yandex**. JavaScript-мост находится в `yandex.js`, вызовы Unity — в `Assets/Plugins/WebGL/YandexGames.jslib`.
Сторонние рекламные сети и плагины не используются. Рекламная интеграция работает только при `UNITY_WEBGL && YANDEX_GAMES && !UNITY_EDITOR`.
В Windows/Steam и в Editor объявления и рекламные кнопки отключены; бесплатное восстановление доступно.

На базе кнопка **Бонусы и восстановление** открывает панель:

| Добровольная реклама | Награда | Повторное получение |
|---|---|---|
| Деньги | 50 денариев | Через 120 секунд |
| Припасы | 1 заряд первого благословления в назначенном каталоге | Через 180 секунд |
| Лечение | Полное восстановление активного отряда, включая павших в выигранных боях | Через 300 секунд |

Таймер начинается после подтверждённой награды, сохраняется между запусками и не запускается при ошибке или закрытии без награды. Время основано на UTC устройства; защиты от ручного изменения часов и серверной экономики здесь нет.

После победы или поражения доступна добровольная реклама за дополнительную сумму, равную золоту последнего боя (убийства плюс контракт при победе). Она поступает сразу в денарии школы. Бонус можно получить один раз; повторный callback не начисляет деньги снова. Следующий бой заменяет прошлое предложение. После возврата из базы к невыбранной награде победного боя предложение также доступно. Поражение не сохраняется как активный забег, поэтому его предложение не восстанавливается после перезапуска игры.

Межстраничная реклама вызывается после нажатия «К награде» или перезапуска после поражения, только в логической паузе. Локальный интервал — минимум 180 секунд; после наградной рекламы он отсчитывается заново. Дополнительно частоту регулирует Яндекс. При недоступности рекламы переход продолжается.
Стики-баннер запрашивается в меню и на базе и скрывается на арене. Шаблон резервирует место справа на широком экране и снизу на узком; в консоли необходимо выбрать соответствующее размещение и включить управление через API.

Подключены LoadingAPI.ready, GameplayAPI.start/stop, game_api_pause/resume, потеря фокуса, остановка симуляции, аудио и UI-ввода при полноэкранной рекламе. Ошибка SDK не блокирует саму игру. В Editor награды не имитируются.

## Здоровье между боями

Сохраняется индивидуальная доля HP каждого бойца по ID конфига и порядковому номеру внутри этого типа. 50 из 100 остаётся 50 из 100 в следующем бою и после визита на базу. При изменении максимума HP сохраняется доля ранений: 50% от нового максимума. Смена формации не лечит.
Павшие после победы остаются с 0 HP, не выходят на арену и не занимают боевые места до восстановления. Новые бойцы из пополнения приходят здоровыми. При полном поражении забег заканчивается по прежним правилам.
На базе начинается двухминутный отдых; после него кнопку восстановления можно нажать бесплатно. Отдых не лечит автоматически, его срок сохраняется при уходе и перезапуске. Мгновенная рекламная награда — необязательная альтернатива ожиданию.
Старые сохранения версии 5 мигрируют в 6: постоянные покупки остаются, бойцы без сохранённых ранений начинают здоровыми. Незавершённый бой при перезагрузке повторяется с его исходным здоровьем и исходным золотом, как ранее повторялся контракт.

Документ баланса v1 описывает прежнее автоматическое полное лечение после каждого боя. Его замеры длительности нельзя переносить на режим сохранения ранений без нового баланса. Значения контента намеренно не менялись.

## Сборка

В Unity: **Gladiator Game → Yandex → Configure Web build**, затем **Build release**.
Скрипт `Assets/Code/Editor/YandexBuild.cs` включает define YANDEX_GAMES только для WebGL, шаблон PROJECT:Yandex, gzip с decompression fallback, кэш данных и Low stripping для контейнера зависимостей. Выход — **Builds/Yandex**; результат — `Builds/yandex-build-result.txt`.
Обычные desktop-сборки не вызывают SDK. Для обычной WebGL-площадки снимите YANDEX_GAMES и выберите обычный шаблон.
Сейв Яндекс-сборки использует ключ `lupanarium.yandex.save`, desktop/Editor — прежний `lupanarium.save`. Хранилище — локальный PlayerPrefs/IndexedDB; облачная синхронизация и авторизация не добавлялись.

## Действия в консоли Яндекс Игр

1. Создайте или откройте черновик нужной игры. Название, изображения и поддерживаемые устройства заполните для фактической версии контента.
2. Подключите монетизацию в своём кабинете. Этот шаг зависит от аккаунта и не выполняется кодом SDK.
3. Загрузите ZIP: index.html должен лежать в корне, рядом Build, StreamingAssets при наличии и yandex.js. SDK-файл не скачивается и не кладётся в архив.
4. Для sticky включите «Использовать API для показа sticky-баннера». На компьютере — справа, на мобильных — снизу. Проверьте, что он не перекрывает кнопки.
5. Откройте черновик с debug-панелью (`debug-mode=16`). Проверьте Game Ready после готовности интерфейса, начало/остановку геймплея и отсутствие звука при сворачивании и рекламе.
6. Проверьте успешный просмотр, закрытие без награды, отсутствие рекламного заполнения, потерю сети, повторный клик, переход на базу, перезагрузку с ранеными и восстановление таймеров.
7. Отдельно проверьте каждый заявленный тип устройства и ориентацию. Локальная desktop-проверка не подтверждает готовность мобильной заявки.

Публикация и прохождение модерации не выполнялись. Тестирование SDK callbacks с имитацией не заменяет проверку реальной рекламы в черновике.
