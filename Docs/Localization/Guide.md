# Локализация игры и добавление новых текстов

Руководство для ProjectLupanarium. Поддерживаются русский, английский и турецкий языки. Все переводы хранятся отдельно от игрового баланса: новые названия и описания можно переводить без изменения характеристик, цен или идентификаторов объектов.

## Как выбирается язык

В сборке WebGL с флагом YANDEX_GAMES игра получает язык из `ysdk.environment.i18n.lang`. Значения `ru`, `en` и `tr` выбирают соответствующую локаль Unity Localization. Для других языков используется английский. Язык браузера не подменяет язык платформы.

Выбор происходит в Bootstrap до открытия главного меню. Игра асинхронно загружает таблицы и устанавливает `LocalizationSettings.SelectedLocale`. Если SDK не отвечает в течение 15 секунд или сообщает ошибку, используется английский. За пределами Яндекс WebGL язык выбирается по языку системы: русский, турецкий, иначе английский.

Страница загрузки тоже переведена. Пока SDK ещё не ответил, она показывает английский текст; после ответа — язык платформы. Ручной переключатель языка в меню не добавлен.

Основание: пункт 2.14 требований Яндекс Игр и поле environment.i18n.lang. Документация: https://yandex.ru/dev/games/doc/ru/sdk/sdk-environment

## Где находятся переводы

Все пути ниже указаны от корня проекта.

| Что | Где |
| --- | --- |
| Исходник переводов для редактирования | Tools/Localization/translations.json |
| Таблицы строк GameText | Assets/Localization/Tables |
| Локали ru en tr | Assets/Localization/Locales |
| Настройки пакета | Assets/Localization/LocalizationSettings.asset |
| Общий шрифт с кириллицей и турецкими буквами | Assets/Localization/Fonts/GameFont.asset |
| Получение текста в коде | Assets/Code/Infrastructure/Platform/L10n.cs |
| Импорт и настройка интерфейса | Assets/Code/Editor/LocalizationSetup.cs |

В исходнике 217 ключей, для каждого заполнены поля `ru`, `en`, `tr`. Поле `context` помогает найти, где используется текст. В существующих строках ключом часто служит исходная фраза. Для новых строк удобно выбирать постоянные ключи вроде `ui.shop.buy` или `unit.new_unit.description`.

JSON — основной редактируемый источник. Импорт переносит его значения в String Tables. Если исправить только таблицу в Unity, следующий импорт перезапишет совпадающую запись значением из JSON. Не запускайте `build_source.py` и `localize_code.py` для обычного редактирования: это инструменты первоначального переноса, а не повседневный импорт.

## Как изменить существующий перевод

1. Откройте `Tools/Localization/translations.json` в редакторе с поддержкой UTF-8.
2. Найдите запись по `key` или исходной фразе. Измените нужные значения `ru`, `en`, `tr`. Сам ключ оставьте прежним.
3. В Unity выполните `Gladiator Game → Localization → Import translations JSON`.
4. Выполните `Gladiator Game → Localization → Validate tables` и убедитесь, что в Console нет ошибки.
5. Проверьте экран на трёх языках и соберите новый билд. Переводы не загружаются с внешнего сервера: уже опубликованная игра изменится только после загрузки новой сборки.

## Как добавить новый текст

Добавьте объект в массив `entries` файла JSON. Между объектами нужна запятая. Пример новой подписи с ценой:

```json
{
  "key": "ui.shop.buy",
  "ru": "Купить за {0}",
  "en": "Buy for {0}",
  "tr": "{0} karşılığında satın al",
  "context": "Кнопка покупки в новом магазине"
}
```

После добавления выполните импорт. Непустые значения обязательны для всех трёх языков. Ключ должен быть уникальным и оставаться постоянным, даже если формулировка перевода меняется.

Для статичной подписи на сцене или в префабе добавьте к объекту с TextMeshPro компонент `Localize String Event`. В String Reference выберите таблицу GameText и нужную запись. В On Update String назначьте текстовый компонент и его свойство `text` из раздела Dynamic string. Режим вызова — Editor And Runtime, чтобы работал и предпросмотр. Сохраните сцену или префаб.

Для текста, который формируется в коде, используйте помощник в пространстве имён Code.Gameplay:

```csharp
label.text = L10n.Text("ui.settings.title");
priceLabel.text = L10n.Format("ui.shop.buy", price);
```

Сначала добавьте `ui.settings.title` и его три перевода в JSON. Не оставляйте ключ, которого нет в таблице: помощник покажет исходный ключ как запасной текст.

Для существующих фраз поддерживается короткая запись:

```csharp
label.text = L10n.F($"Раунд {round}");
```

Здесь ключ таблицы — `Раунд {0}`. Нельзя передавать уже собранную строку `Раунд 10` в L10n.Text: для каждого числа потребовался бы отдельный ключ.

Не добавляйте статичный Localize String Event к подписи, которую меняет presenter или view: отложенное событие может перезаписать актуальную цену, название или количество. Такие подписи уже получают переводы через L10n и локализованные свойства конфигов.

## Названия юнитов и других объектов

Свойства DisplayName и Description у используемых конфигов и записей UnitClassHudCatalog проходят через L10n.Text. Сериализованные названия, идентификаторы, ссылки на каталоги и значения баланса этой задачей не менялись.

Для нового юнита, здания, предмета, формации, контракта или благословления добавьте две записи в JSON: для названия и описания. В полях Display Name и Description конфига можно указать эти ключи, например `unit.new_unit.name` и `unit.new_unit.description`. Либо оставьте русскую фразу и используйте её точную копию как ключ, как в существующих объектах. Пробелы, переносы и регистр должны совпадать.

В UnitClassHudCatalog отдельно переводятся подписи и описания для карточек класса и отряда. Если новый код выводит строку напрямую из нового поля, сам по себе JSON её не заменит: добавьте L10n.Text в место чтения или подключите Localize String Event.

Гладиаторская и будущая версия с брейнротами могут использовать разные ключи названий и описаний в одной таблице, например `gladiator.unit.name` и `brainrot.unit.name`. Системные ID объектов не переводите: по ним сохраняются покупки и прогресс.

## Числа переносы и шрифт

`{0}`, `{1}` и другие подстановки нужно сохранять во всех переводах. Их порядок можно менять по грамматике языка. Формат `{0:0.0}` означает число с одним десятичным знаком, `{1:00}` — две цифры, например секунды таймера. В таблицах выключен Smart Format: здесь используется обычный string.Format.

Для новой записи с подстановками проверка сравнивает переводы между собой. Для старой записи, где ключ сам является шаблоном, она также сверяет их с ключом. Фигурные скобки обычного текста в шаблоне записываются как `{{` и `}}`.

В JSON перенос строки записывается как `\n`, кавычка внутри значения — как `\"`. Теги TextMeshPro, например `<color=#806F55>` и `</color>`, сохраняйте парными. Не переводите имена тегов и коды цветов.

GameFont содержит кириллицу и турецкие Çç Ğğ İı Öö Şş Üü. Статичные подписи используют авторазмер в пределах исходного оформления. Для новой длинной строки сначала расширьте область или разрешите перенос, затем корректируйте размер. Не полагайтесь на уменьшение текста до нечитаемого размера.

## Проверка и сборка

Статичные подписи можно проверять через `Window → Asset Management → Localization Scene Controls`. Выбирайте Russian, English и Turkish. Динамические тексты проверяйте в запущенной игре начиная со сцены Bootstrap; запуск отдельной Arena в редакторе пропускает начальную загрузку локализации.

В проекте есть тесты полноты переводов, подстановок, наличия символов в шрифте и связей интерфейса. Запускайте EditMode-тесты через Unity Test Runner. Отдельно просмотрите длинные турецкие подписи, цены, таймеры, экран поражения и подтверждение полного сброса.

Для локальной проверки WebGL запустите `Tools/Yandex/serve-preview.py --mock-sdk`, используя Python. Откройте `http://127.0.0.1:8765/?lang=ru`, затем варианты `?lang=en` и `?lang=tr`. Это только тестовый SDK; параметр URL не меняет язык настоящего Яндекс SDK. Тестовые файлы лежат вне Assets и не попадают в архив игры.

Переключите платформу Unity на WebGL. Команда `Gladiator Game → Yandex → Build release` проверяет таблицы, собирает Addressables и создаёт игру в Builds/Yandex. В ZIP должны лежать index.html, Build, StreamingAssets и файлы шаблона; папка StreamingAssets содержит переводы и обязательна. На платформе отдельно выберите поддерживаемые языки русский, английский и турецкий.

## Ускорение боя

Во время боя кнопка переключает скорость ×1 → ×2 → ×4 → ×1. Используется ArenaSimulationClock: ускоряются перемещение, атаки, боевые эффекты и анимация юнитов. Скорость сохраняется между раундами, пока открыта сцена арены; после выхода на базу и возвращения начинается с ×1.

Рекламные задержки и бесплатный отдых продолжают использовать реальное время. Рекламная пауза и потеря фокуса останавливают бой независимо от выбранной скорости. Кнопка скрыта на экранах выбора и результатов.
